# Financial data erasure — work in progress, not deployable

The previous preservation decision was superseded: the user authorized erasure of app-stored wallet, bank, transaction, budget and related financial data for all accounts, including records of unknown ownership. Subscriptions, subscription reminders, original phone SMS and unrelated application data must remain. This authorization does not mean erasure has happened.

The adjacent SQL migration is a **draft only**. It is intentionally outside the migration directory and will not run as part of normal database migrations. Do not deploy, manually run, or copy it into the migrations directory until the release blockers below have been resolved and verified. No production deletion or deployment has been performed.

## Work completed locally (not released)

- Android SMS receiver, wallet capture/cipher/storage implementations and their method-channel write/read bridges were removed. The retained subscription reminder methods, voice, archive and Focus Shield bridges remain. Focus Shield now rejects SMS-app notifications before accessing their content; its opt-in, memory-only inbox for explicitly supported non-SMS messaging apps remains. Flutter money/queue screens and client write paths were removed; the weekly Focus report no longer requests or sends spending data. Subscription CRUD still uses its existing API path. Native wallet cleanup independently attempts each preference store, each key alias and notification cleanup, and matches the retired notification channel instead of cancelling shared notification IDs (the focus timer also uses 999). On Android versions without notification channels, an old financial notification may remain until dismissed; the cleanup does not risk cancelling an unrelated notification.
- A narrow startup/sign-out cleanup attempts retired Flutter preferences, the old secure-storage token and Android wallet Keystore/preferences, independently and on every launch. It does not delete all preferences, all secure storage, subscriptions, reminders or original SMS. Native and Flutter changes have not been compiled or executed on a device; retry and cross-platform behavior still need validation.
- Production routing mounts a dedicated subscription controller, service and PostgreSQL repository and a token-revocation-only router after the existing HTTP 410 guards. Backend SMS ingestion/analysis and token issuance were removed, retaining authenticated session-scoped legacy token revocation for mixed-version rollout. The legacy Money controller, service, repository, routes and test-only harness were removed, together with wallet-write middleware and transaction, payment, budget and report validation/DTO code. Retained subscriptions still resolve legacy categories until the draft detaches them; category-archive race and amount/scale behavior are covered against the production subscription app. Registration does not create financial categories. Historical migrations, deletion/retention cleanup and some shared database types still reference financial tables and need review. Unused retired endpoints and financial/SMS schemas were removed from the OpenAPI generator and generated document, and the sample analytics and preview no longer promote financial features. The cross-feature money reader was reviewed and reads only retained subscriptions. The erasure SQL is not in the runtime migration directory.
- The v1 account archive keeps its original ordered section names and zero counts for retired categories, transactions, budgets and SMS-ingest devices, but does not query or export those tables, including during pre-erasure rollout. The legacy metadata export also returns an empty categories array without querying categories. Subscriptions, notes, reminders and other unrelated data remain exportable; preexisting downloaded archives remain external copies. SQL-harness and isolated PostgreSQL tests cover exclusion, precision, account scoping and the preserved export contract.
- Retained active subscription reads now project renewal dates from the stored first date and anchor without recording payment or mutating data. Detail/list/search and day/dashboard use the projection; list cursor keys remain the stable stored date plus ID, so the mobile list fetches all pages then sorts displayed dates. The mobile monthly estimate uses the server's rounded four-decimal monthly equivalent, adds with integer precision separately by currency and excludes inactive subscriptions. It fails closed for malformed/duplicate pages (up to 5,000 display items; reminder snapshots retain their 200-item limit). Concurrent edits across pages can still change results; this is not a database snapshot. Targeted isolated PostgreSQL tests include past weekly dates, all query surfaces, unchanged stored rows, and 31-item pagination after the draft deletion. Mobile tests were authored but not executed.
- Current backend formatting, source/test typechecks and lint pass. All historical migrations ran through the real migration CLI on isolated PostgreSQL 16.2 with pgcrypto, citext and pg_trgm (extensions built locally), using a distinct non-superuser migrator. The full suite on this freshly migrated database passed 631 tests; the two destructive/opt-in draft tests were skipped there and passed separately: rollback/FK test on the migrated database and committed/concurrency test on another freshly migrated, dedicated disposable database. After committed erasure, 23 subscription, query and reminder integration tests also passed. The committed test additionally verifies that the restricted runtime can schedule and purge an account without deleting another account’s subscription. This local setup still cannot prove production schema/roles, hosted CI or production deployment behavior. CI is configured for both tests but has not run on these changes. Root contracts passed 160/160. Thirteen standalone JVM renewal calculation checks passed using Java 17 and Eclipse JDT; they cover local 09:00, DST, month ends, off-cycle first dates and long-past anchors, but not Android alarm delivery. Three focused Kotlin source tests passed using the project Kotlin compiler version and temporary Android/JUnit stubs; this is not a real Android build or device test. Flutter and Android tests/builds have not run. A standalone WASM formatter parsed and formatted changed Dart sources with the project language level, but this is not Flutter analysis or official CI formatting.

## Blockers

- Review remaining historical/shared financial table types and deletion/retention compatibility where safe, without dropping unrelated account, subscription and reminder coverage. Registration no longer seeds money categories, so that it does not conflict with the draft write revocation; this change alone does not erase any existing rows.
- The rollback-only draft test seeds two accounts and checks erasure, preservation, privileges and rollback; it now also asserts the complete expected catalog of incoming foreign keys to retired tables. The separately opt-in committed test requires a loopback host, an exact dedicated database name, empty user/financial/audit tables, distinct roles and a destructive-test acknowledgement. Both also passed locally against freshly migrated PostgreSQL 16.2 with all required extensions and distinct roles. The draft now aborts and rolls back if PUBLIC, inherited or assumable roles still allow retired writes or if the runtime can assume an owner/superuser role; the rollback test covers PUBLIC column grants and a separate local test covered a SET ROLE-only grant. This is not protection against later role/grant changes or privileged SECURITY DEFINER paths. A fresh hosted CI run, review of production schema/role inheritance, wider audit/event history and external data copies remain release blockers. The locks and privilege checks do not replace draining old instances or identify unknown historical storage.
- Validate the retained-subscription projection and mobile pagination/summary in Flutter/Android CI and physical Android tests. Page-by-page list reads are not a snapshot under concurrent edits; the API documents its stable stored-date cursor order. Reminder scheduling must still be verified at 09:00 device-local two days before each renewal, including timezone changes and reboot.
- Finish and verify Android device cleanup, confirm the reviewed storage keys and aliases against deployed historical versions, verify the secure-storage cleanup on each supported platform, and ensure retired code cannot recreate local data. Startup cleanup has not been built or tested on a device. Offline or never-updated installations cannot be remotely cleaned by it.
- Establish a deployment plan to drain old API instances and background writers before erasure, avoid older clients recreating data, and verify the result after deployment. Review account archives, external exports, logs, backup retention and disaster recovery: restoring an older backup can resurrect deleted data and requires reapplying a verified erasure before service resumes. External copies and original phone SMS are outside the scope of the app database operation.
- Obtain full hosted CI, signed release and physical-device validation. Verify automatic subscription reminders at 09:00 local time two days before every renewal and Digital Detox / Focus Shield accessibility behavior. AI streaming/error handling still requires live/device verification.

The older retirement report describes the earlier, preservation-only baseline; read it as historical rather than as the current authorization or a claim that data deletion is complete.
