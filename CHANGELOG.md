# Change log

## Unreleased — Hybrid AI slice AI-1 (provider-neutral core), 2026-11-12
- Backend: the AI proxy now builds one provider-neutral request (`backend/src/features/ai/providers/ai-provider.ts`) and a Gemini adapter translates it. `AI_PROVIDER` (default `gemini`) accepts only `gemini`; any other value stops startup and there is no fallback to another provider. No API change: `/ai/chat` and `/ai/chat/stream` keep their shapes, quotas and `AI_ENABLED`.
- AI0-F3: the server prompt and the reply-language rule go through Gemini's system-instruction field; user turns carry only the user's text.
- AI0-F5: explicit safety settings on harassment, hate speech, sexually explicit and dangerous content at `BLOCK_MEDIUM_AND_ABOVE` (Gemini 2.5 and later apply none by default). A refused prompt or a reply stopped by the filters fails as `blocked`: never shown as text, also not in part when streaming; clients get the same generic error, and only the kind is logged.
- AI0-F9: the fallback reply language is clearly Arabic script in the latest message, else the app's hint, else the account locale, else English (was always Arabic). The model still answers in the language of the message.
- D6, app: deleted the 16 `AiService` prompt methods no screen called, including workout and meal plans (AI-0 counted 17). No UI change.
- AI notice: "Don't type passwords, personal details or sensitive information", in six languages.
- Unpaid Gemini tier for the closed test (owner decision): `docs/ai/gemini-free-tier.md` (Railway limits, Play countries, policy and Data safety, switching to paid). Tester guide: daily limit and the restart workaround. Report: `docs/reports/hybrid-ai-ai1-report-2026-11-12.md`.

## Unreleased — Hybrid AI slice AI-P and release preparation, 2026-11-12
- Play policy, in-app privacy policy (AI-P-F5): Profile → Privacy policy opens the published policy in the browser through a plain Android view intent on the existing platform channel (`openHttpsUrl`; https only, checked in Dart and Kotlin; no new library). The link comes from the `android-release` variable `ANDROID_PRIVACY_POLICY_URL`, which the signed job validates before signing and passes to the APK and App Bundle builds; the repository holds no URL and builds without it hide the entry. Three strings in six languages. Tests: Dart (link rules, channel, Profile entry in English and Arabic at 200% text), Kotlin `HttpsLinkTest`, CI YAML test. Device check PP-1.
- Play policy, account deletion outside the app: owner procedure `docs/auth/account-deletion-requests.md` and owner SQL `docs/auth/sql/schedule-account-deletion-on-request.sql` for requests sent by email. The SQL repeats the in-app scheduling (14 days, everything revoked, same audit event as a system action); a unit test fails if the two drift apart. Device check DEL-1. Google Docs copies of the privacy policy and the deletion page are in the owner's Drive for publishing.
- AI0-F2 / Play AI-Generated Content policy, backend: `POST /api/v1/ai/reports` stores a report of an AI reply: where it was shown (assistant, weekly coaching, analytics insight), the reason (offensive, harmful, inaccurate, spam, other), the app language, an optional note (≤ 500) and the reply text unless the user leaves it out (≤ 4,000). Auth, strict Zod, 10 per hour and 30 per day per user; works with AI turned off. Reports are kept 90 days (nightly purge), included in the JSON export (`aiContentReports`) and erased with the account. Forward-only migration `1792780000000` plus owner SQL `docs/ai/sql/ai-content-reports.sql`; before the SQL the endpoint answers 503 `AI_REPORTS_UNAVAILABLE`. Guide: `docs/ai/ai-content-reports.md`.
- AI0-F2, app: a flag button (tooltip "Report reply", 48 dp) next to AI replies in the assistant, and on weekly coaching and analytics insights only when the AI wrote the text. It opens a sheet with the reasons, "Include the reply" (on), a note, Cancel and Send report. 18 strings in six languages.
- AI0-F1: from about the 12th message, every assistant send failed as "unavailable", because the app sent the whole stored chat (up to 100 messages) and the backend accepts 21 turns and 24,000 characters. The app now sends only the newest answered turns that fit: at most 20 earlier turns, each cut to 4,000 characters, empty bubbles skipped. The message field stops at 4,000 characters.
- AI0-F11 / D9: the Gemini API terms require users to be 18 or older. Every AI feature (assistant, weekly coaching, analytics insights, turning on AI help for Smart Quick Add) asks "Are you 18 or older?" once per account on the phone; declining sends nothing. The AI consent text no longer mentions a personal API key.
- Release: the explicit signed-release job also builds an Android App Bundle, verifies it with the JDK `jarsigner`/`keytool` against the expected certificate (`scripts/verify-android-aab.mjs`) and uploads it with its own symbols (`lifestyle-android-signed-bundle`). Not run: it needs the `android-release` environment.
- Store drafts for the owner: `docs/store/privacy-policy-draft.md` (English and Arabic; names Google Gemini, AI reports and retention), `docs/store/data-safety-draft.md` (Data safety and App content answers, including the Accessibility API declaration that Focus Shield needs and the account-deletion page) and `docs/store/closed-test-tester-guide.md` (Arabic and English, AI scenarios). Device checks AIP-1 to AIP-9 in `docs/mobile/manual-test-checklist.md`. Report: `docs/reports/hybrid-ai-ai-p-report-2026-11-12.md`.

## Unreleased — G6 signed-in devices, G7 widening, G2-F1, Profile localization, 2026-11-11
- G2-F1: `zonedDateTimeToUtc` (relative reminders anchored to a task's due time) now uses the UTC offset in force at the resulting instant. It was one hour off around daylight-saving changes (Cairo, Berlin; New York after the gap). It shares the notification policy's wall-clock helpers (`backend/src/core/time/wall-clock.ts`): a time in a gap moves forward, a repeated time takes its first occurrence. Tests cover Cairo, Berlin and New York, including a midnight that does not exist; 13 of them fail on the old code.
- A3: the Profile account-deletion dialog, messages, banner, status and AI tile use catalog strings in all six languages instead of hard-coded Arabic/English; the literal ratchet drops from 95 to 85.
- P1-F15 (owner decision: wire): the Profile rank card shows level, XP and progress from the Focus Shield XP ledger on this device (with a note saying so) instead of fixed numbers; nothing is shown until the ledger loads. Badges are earned from real data: first task win, first focus session, 7 days in a row with a win. Locked badges are announced to screen readers.
- G6 backend (ADR-047): `GET /api/v1/sessions` lists signed-in devices (metadata only, never `created_ip` or tokens; current session first); `POST /api/v1/sessions/{id}/revoke` signs out one device after the current-password check, revoking its refresh tokens and deleting its push devices in one transaction. Other accounts' ids answer 404; repeating is harmless; 30/60 s per user plus the shared re-authentication budget. Forward-only migration `1792770000000` and owner SQL `docs/auth/sql/auth-sessions-user-revoked.sql` add the `user_revoked` reason; before the SQL the revoke stores `logout`. Guide: `docs/auth/signed-in-devices.md`.
- G6 app: Profile → Signed-in devices lists this device (marked) and the others with last activity; each has a sign-out button with confirmation and the current password; signing out this device is a normal sign-out (local data, widget data and reminders cleared). Loading, empty, error and rate-limit states; hidden during the deletion grace period. Login no longer sends the fixed "Arena Mobile Client" device name. 22 strings in six languages.
- A2 (G7 widening): home tab bar, Tasks and the focus timer pass tap-target, label and contrast checks in Arabic at 200% text on a 320 dp phone. Tasks: the briefing scrolls with the list, day chips grow with the font and are buttons, weekday names and task subtitles (status, priority, due) follow the app language instead of English, the swipe-to-delete background follows RTL and tasks have a spoken delete action. Focus timer: scrolls instead of cutting off its controls, the dial grows with the font and keeps the countdown inside the ring, accessible colours, 48 dp clear-song target. 9 strings in six languages.
- G7 fixes found by the widened tests: each task row is one screen-reader stop (title, checkbox, long-press select and Delete together; the select/delete node had no label), and the focus timer's task picker fills the width instead of overflowing with long titles.
- CI: Flutter pinned to 3.47.9 (owner decision). Flutter 3.50.0 deprecates `package:flutter/material.dart` in favour of `material_ui`, which failed `flutter analyze --fatal-infos` in 68 files on every branch; lifting the pin needs that migration (new dependency, owner approval). See `docs/mobile/flutter-integration.md`.

## Unreleased — feature guide Phase 2: G2 notification policy, 2026-11-11
- G2 (ADR-046; owner decisions recorded): one notification policy for the device and for server push. Each notification is sent, delayed out of quiet hours, combined into the day's summary, or dropped when the master switch is off. Tiers: alarm the user chose / normal reminder / low priority. Defaults change nothing until the user sets something; quiet hours suggest 22:00–07:00.
- Policy in TypeScript (`backend/src/features/notifications/notification-policy.ts`) and Dart (`lib/data/notification_policy.dart`), both run against 28 shared cases (`test/fixtures/notification_policy_cases.json`), including DST gaps and repeated hours in Cairo, Berlin and New York.
- Backend: `notification_preferences` table (forward-only migration plus owner SQL `docs/notifications/sql/notification-preferences.sql`), `GET/PUT /api/v1/notification-preferences` (auth, strict Zod, 30/60 s per user, 503 `NOTIFICATION_PREFERENCES_UNAVAILABLE` before the SQL), export and deletion coverage, archive exclusion, grants in both runtime drafts. The worker requires the policy for push (E3 gate); with no push provider nothing changes.
- App: Profile → Notifications (master switch, quiet hours, alarms during quiet hours, daily limit, account time zone note); task and calendar reminders go through a policy-aware scheduler that re-plans on every change and keeps one content-free summary per day; "Ring as an alarm" switch per timed task (default off: normal reminder, closing P0-F3); settings sync at start and resume; sign-out clears the plan and the calendar registry. 24 strings in six languages; G7 test at 200% Arabic text.
- Report: `docs/reports/feature-guide-g2-report-2026-11-11.md`. Device checks G2-1..G2-9 are NOT RUN.
