# Retirement of money, wallet and financial SMS

> **Historical preservation-only baseline, superseded:** the user later authorized deletion of app-stored retired financial data for all accounts while preserving subscriptions, reminders and original SMS. The deletion work is incomplete and has not been deployed. See [the erasure work-in-progress status](drafts/ERASURE_STATUS.md); the draft migration is deliberately outside the migrations directory. Do not treat the preservation statements below as the current product decision.

## Product decision

On 2026-11-06 the user canceled the complete money feature, including budgets, transactions, wallet, bank-message capture and the proposed independent phone/OTP wallet account. Subscriptions remain accessible from More, with their existing automatic renewal reminders two days before renewal at 09:00 device-local time. No mobile payment UI is added. No provider account, credentials, charge or actual OTP SMS was created.

## Code boundary

- The Flutter home shell no longer displays the money screen, issues wallet ingestion tokens or flushes wallet transaction/candidate queues. The old money deep link resolves to Tasks; Notes uses the corrected navigation index. The More screen opens subscriptions. Renewal synchronization on home startup/resume remains.
- The Android manifest no longer requests `RECEIVE_SMS` or registers the wallet `SMS_RECEIVED` receiver. Existing local pending entries are not intentionally deleted or replayed by the new home shell. This cannot retroactively stop an old installation before upgrade, undo a request already sent, or guarantee storage survival through app removal/device loss.
- On the updated backend app, HTTP money/ingest retirement guards return 410 before the historical routers for budgets, financial transactions, categories, reports, token issuance and SMS analysis/ingest, including wallet variants and subscription payment. Subscription collection/item operations and authenticated legacy ingest-token revocation remain. This is an API-breaking change for older clients. It applies only after the updated server is deployed; an already-started request may complete.
- No migration, cleanup or bulk deletion is performed. Existing financial rows and device queues remain subject to their existing retention, account deletion, export, backups, storage failure and device lifecycle. This is not a promise of indefinite preservation, encryption, forensic ownership, or a secure review/recovery interface. Account export is an explicit existing action and may include historical financial data. Historical code, database schema and tests remain for preservation and compatibility; their presence is not an enabled product feature. In particular, unit and PostgreSQL tests under `tests/support/legacy-money-test-app.ts` exercise **unmounted historical routers**, not production HTTP availability.
- The normal production app has a separate regression test for the retirement boundary, retained subscriptions and preservation of an existing synthetic transaction. This does not verify a deployed server, upgrades, old Android installs, concurrent in-flight requests, real messages, or physical reminder delivery. No test should use real bank or wallet SMS.

## Validation and remaining work

Backend unit tests passed 536/536. Focused tests on the actual production HTTP composition, retained subscriptions, reminders and account cleanup passed 25/25 as the non-superuser runtime role on isolated synthetic PostgreSQL/Redis; a further 49/49 tests exercise retained historical components in a test-only harness and account cleanup. Root source contracts passed 179/179. Full backend testing against the synthetic fixture had 820 passes and 15 failures: the fixture lacked the wallet-owned migration and trigram extension/index, and was run as a superuser rather than the runtime role. These results do not prove that hosted CI will pass. Local PostgreSQL is a partial-extension fixture and cannot establish that hosted fresh migrations, a production configuration or a physical device works. Flutter/Dart and Android device tests require the hosted toolchain and physical hardware. The prior dated remediation report is historical, and the release remains NO-GO pending full hosted CI, subscription reminder verification, and the independent AI/Focus Shield/device blockers. Canceled wallet-phone and provider tasks must not be resumed without a new decision.
